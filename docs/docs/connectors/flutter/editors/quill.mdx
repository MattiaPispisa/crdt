# flutter_quill

[`crdt_lf_quill`](https://pub.dev/packages/crdt_lf_quill) makes a
[flutter_quill](https://pub.dev/packages/flutter_quill) editor collaborative.
`CrdtQuillBinder` keeps a `QuillController` in step with a
[`CRDTFugueRichTextHandler`](../../../use-cases/rich-text.mdx), so several peers
can edit the same document, with bold, links, headings, lists and embeds.

```sh
flutter pub add crdt_lf crdt_lf_flutter crdt_lf_quill flutter_quill
```

## Usage

flutter_quill reads its texts from its localizations: add its delegate to the
app, or the toolbar throws `MissingFlutterQuillLocalizationException`.

<RecipeSnippet id="quill-editor" file="main.dart" region="app" />

Register a rich text handler on the document, provide the document with
`CrdtProvider` (from [`crdt_lf_flutter`](../index.mdx)), and put the binder
above the toolbar and the editor. The `State` owns the controller:

<RecipeSnippet id="quill-editor" file="editor_page.dart" region="state,bind" />

Edits made in the editor go into the handler. Changes from other peers show up
in the editor.

- **Keep `crdtQuillUnknownEmbedBuilder`.** Without it, `QuillEditor` throws in
  its build as soon as a peer writes an embed it has no builder for, and the
  base editor has no builder for images or videos.
- **Key the toolbar on `controller.document`.** The binder gives the controller
  a new `Document` when it reads a handler. A widget that listens to
  `controller.changes` keeps the stream of the document it was built with, and
  the undo and redo buttons of `QuillSimpleToolbar` do so. Key the toolbar on
  `controller.document` and rebuild it with the controller, as above.
- **Hide one `ChangeSource`.** `crdt_lf` and `flutter_quill` both export a
  `ChangeSource`. If you import both libraries in one file, hide the `crdt_lf`
  one: Quill code uses the Quill `ChangeSource`.

A change that arrives during a build (the first read of the handler, a new
controller, a write made in `initState`) reaches the editor at the end of that
frame, so a widget that listens to the controller can sit anywhere.

## How it works

The binder gives the controller its own `Document`. That document writes every
local change into the handler right after Quill applies it, in one
transaction. A remote change becomes a Quill delta, applied as
`ChangeSource.remote`. When the binder reads the whole handler again, it applies
the difference as `ChangeSource.silent`, so the selection stays.

Do not assign `controller.document` yourself: the new document is not bound.
Its edits stay out of the handler, and the next read of the handler replaces it.

The converters are exported, so you can build your own binding:

- `richTextDeltaFromQuill(change, before)`: a Quill change to a `RichTextDelta`.
- `quillRichTextWriter.write(handler, delta)`: writes a `RichTextDelta` into the
  handler.
- `quillDeltaFromRichText(delta, before)`: a `RichTextDelta` to a Quill change.
- `quillDocumentFromSpans(spans)`: the handler value as a Quill document.

Pass `document:`, the Quill document `before` comes from, to the two delta
converters: an embed replaced in one change then maps to an update.

### Units

Quill counts UTF-16 code units. The handler counts runes, so an emoji is one
place in the handler and two in Quill. The converters translate the offsets
against `before`, the plain text the change applies to.

An edit always lands on whole runes. A replace that starts or ends inside a
surrogate pair takes the whole emoji, and an insert inside a pair goes before
it. A lone half surrogate stays one place in the handler.

### Attributes

Block keys (`header`, `list`, `blockquote`, `code-block`, `indent`, `align`,
`direction`, `line-height`) live on the `'\n'` that ends the line. They never
grow onto new text. Inline keys live on the text. A key with a `null` value
removes the attribute.

`quillMarkExpand(key)` says how a format grows when someone types at its edge:

| Key | Grows |
| --- | --- |
| Block keys | never (`MarkExpand.none`) |
| `link` | never (`MarkExpand.none`) |
| `style`, `displayWidth` (the size of an embed) | never (`MarkExpand.none`) |
| Any other key (`bold`, `italic`, `color`, ...) | after its end (`MarkExpand.after`) |

New text in the handler takes the formats on its left. Quill sends the exact
attributes of each insert, so after an insert `quillRichTextWriter` sets the
formats Quill asked for and removes the others. When they already match, it
writes nothing more.

### Embeds

Quill embeds (images, videos, formulas) are
[embeds of the handler](../../../use-cases/rich-text.mdx#embeds), and back. An
embed is one position in the handler.

- **Images and videos** of `crdt_lf` (`insertImage`, `insertVideo`) and native
  Quill images and videos are the same thing. A Quill `{"image": url}` comes to
  the handler as `{"type": "image", "src": url}`, so `span.image` reads it. An
  image with only `src` goes back to Quill native. One with more fields (`alt`,
  `width`, …) comes as `{"crdt_lf": map}` (`crdtQuillEmbedType`), so no field is
  lost when Quill writes it back.
- **Size.** The displayed width (`displayWidth` in the handler) is the `width`
  of the Quill `style` that the image resize writes and the image builders
  read. The rest of that `style` (height, alignment) is kept as Quill wrote it.
- **Other embeds.** Any other handler embed that is not a map of one key comes
  as `{"crdt_lf": map}` too. To show these, pass your builders through
  `crdtQuillEmbedBuilders`: the builder of the embed's `type` (or of the first
  key of the map that has one) shows it, else a small box (`fallback`). That
  builder gets one value and the style, not the other fields, and draws inline.
- `crdtQuillUnknownEmbedBuilder` shows every other embed with the same
  `fallback`. Without it, an embed with no builder makes `QuillEditor` throw in
  its build.

  ```dart
  QuillEditorConfig(
    embedBuilders: crdtQuillEmbedBuilders([...myBuilders]),
    unknownEmbedBuilder: crdtQuillUnknownEmbedBuilder(),
  )
  ```

- An embed replaced by another in one Quill change becomes an **update** of the
  same embed in the handler, so a concurrent format on it survives.
  `replaceText` with an `Embeddable` makes two Quill changes, so it is a delete
  and an insert.
- A block embed (a video, a full-width image) keeps its own `'\n'`, which holds
  the block attributes.
- `embedTypes` lists the embed types the editor may write (`image`, `video`, a
  custom `type`); `null` takes all. It filters this editor only: a peer can
  still write any type, so keep `crdtQuillUnknownEmbedBuilder` in place.
- An embed of a type out of `embedTypes`, or with data the handler refuses
  (above `maxEmbedBytes`, nested too deep, a `NaN`), goes to `onUnsupported`.
  Each embed inserted in the editor is checked this way before it is written.
  A refusal deletes no embed:
  - when nothing else is written, the whole replace is dropped: the selection
    stays, its text included, and the caret does not move;
  - when something else is written, such as the text of a paste, the selected
    text goes and the embeds of the selection stay.
- An attribute value the handler refuses (a list, a `NaN`) goes to
  `onUnsupported` as `{key: value}`. The attribute is dropped, and the rest of
  the edit is written.
- Upload and rendering stay with the app. Keep large media outside the document
  and put a URL in the embed.

### The last newline

A Quill document always ends with a `'\n'`. The handler stores that last newline
only when it is needed:

- When the last line is plain, the last `'\n'` stays out of the handler. Two
  peers that start from an empty editor do not get two newlines.
- When the last line has a block attribute (for example a heading), the handler
  stores its `'\n'` with the attribute.
- When an empty plain last line follows a line with a block attribute, the
  handler stores that last `'\n'` too. Without it, the empty line would be lost.

## Undo

The binder keeps changes from other peers out of the controller's undo stack,
like `History(userOnly: true)`. Undo takes back your own edits only, and the
undo is sent to the other peers like any other edit.

For a history that understands formats and concurrent edits, pass a
[`CRDTUndoManager`](../../../use-cases/undo-redo.mdx) to the binder. The editor
then undoes through the manager, and the toolbar buttons follow it. A new
manager, or none, drops the steps of Quill's history.

```dart
final undo = CRDTUndoManager(
  document,
  trackedOrigins: {crdtQuillOrigin}, // only the edits made in the editor
)..track(handler);

CrdtQuillBinder(id: 'page', controller: controller, undoManager: undo, ...);
```

Typing close in time is one undo step (see `captureTimeout`). A format (bold,
a link, a heading) is always a step of its own, so typing a word and making it
bold takes two undos. Call `undo.stopCapturing()` to end a step by hand. The toolbar buttons refresh on
editor changes only: after `undo.clear()` they keep their state until the next
change.

## Projection check

After each local write and each remote change, the binder compares the lengths
of the editor and the handler, and reads the handler again on a mismatch. A
debug build also compares the full content and throws on a mismatch, while
`debugVerifyCrdtQuillProjection` is `true` (the default). In the
[benchmarks](../../../benchmarks/crdt_lf_quill.mdx),
a local keystroke on a 50000-rune document takes 2.17 ms with the length check
and 3.40 ms with the full check.

## Remote cursors

The binder publishes the local selection, and `CrdtQuillCursorsOverlay` draws
the other peers' carets and selections over the editor, with the labels and the
motion of [`CrdtTextCursorsOverlay`](../text-fields.mdx#remote-text-cursors).
Anchors are stable positions: they follow any edit, and they belong on a
presence channel, such as the
[awareness plugin](../../sync/plugins.mdx#awareness-plugin), never in the
document history.

```dart
CrdtQuillBinder(
  id: 'page',
  controller: controller,
  onSelectionAnchorsChanged: (base, extent) => publishPresence(base, extent),
  child: CrdtQuillCursorsOverlay(
    id: 'page',
    cursors: remoteTextCursors, // List<CrdtTextCursor> from presence
    child: QuillEditor.basic(
      controller: controller,
      focusNode: focusNode, // kept in a State, see below
      scrollController: scrollController,
    ),
  ),
);
```

Keep the `FocusNode` and the `ScrollController` of the editor in a `State`.
Cursors change often and rebuild the editor, and `QuillEditor.basic` makes new
ones on each build when you pass none: the user would lose the keyboard after
the first keystrokes.

The callback fires while the focus is inside the binder, and once with `null`s
when the focus leaves or the handler is deleted. For mouse pointers, wrap the
editor in [`CrdtAwarenessCursorsOverlay`](../presence.mdx).

## Limits

- Two peers that format the plain last line at the same time both store a last
  `'\n'`, so the document gets one extra line.
- The editor keeps its own selection, moved by each remote change.
- A remote selection is one caret high: it covers part of a line that holds a
  tall inline embed.
- Remote cursors move on document changes. After a layout change alone, such as
  an image that finishes loading, they stay until the next change.
